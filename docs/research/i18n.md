# Translations (i18n)

Written 2026-10-04. Covers what the app's Spanish (Spain) translation rests
on and what is still unchecked against the game in Spanish.

## How it is built

- Interface text: [Project Fluent](https://projectfluent.org) messages in
  `crates/arclens-i18n/locales/<lang>/*.ftl` (`en`, `es-ES`), compiled in.
  Fluent handles plurals per language (`[one]` / `*[other]`), which a
  future language with more forms (Polish, Russian) needs.
- The language is a setting (Settings → Language: system, English,
  Español (España)). "System" reads the OS locale with `sys-locale`;
  any `es-*` locale gets Spain's Spanish, anything else English.
- The app sends the language to the overlay in `Configure.lang` (an
  optional field, so older overlays ignore it).
- Tests check that every language has the same message ids and the same
  variables, and that every `t!("…")` in the code names a message.

## Game data

- **Item, quest, station and project names and item descriptions** come
  from RaidTheory's dataset, whose localised strings are keyed by language
  (`{"en": …, "es": …, "de": …}`, ~20 languages). Verified 2026-10-04 on
  the dataset checkout: items, quests, hideout and skill nodes have `es`.
  Source: <https://github.com/RaidTheory/arcraiders-data>.
- The catalogue is built in the chosen language (one cache file per
  language); names in the other language are kept as `aliases`. Item
  matching (tooltip OCR, the overlay's quick search, the Items search) and
  quest / station matching try every name, so an English game with a
  Spanish app (or the reverse) still matches. OCR text is compared
  without accents (`ESCÁNER` = `ESCANER`).
- **Map names**: RaidTheory's `maps.json` `es` values look like slugs of
  real translations (`presas_campos_de_batalla`, `ciudad_enterrada`,
  `la_puerta_azul`, `el_puerto_espacial`; `Mareas divididas` is clean).
  The app shows them as written titles ("Campos de batalla de la presa").
  **Unverified** against the game in Spanish.
- **Map conditions, marker kinds, item types, rarities, preset names**:
  translated by us in `game.ftl` / `app.ftl`. **Unverified** against the
  game's own Spanish terms (RaidTheory's `map-events.json` only has `en`,
  `JP` and `zh-CN` for conditions).
- Quest markers: MetaForge's quest-marker subcategory is the quest's id
  (`a-bad-feeling`; 29 of 30 on Dam match a RaidTheory quest id,
  2026-10-04), so they show the quest's name in the chosen language. The
  app passes these names to the overlay in `Configure.names`.
- Place names on the map (MetaForge labels), quest-marker objective text
  (MetaForge's `instanceName`, written by its users) and most ARC enemy
  names stay as the data has them. Everything ARClens itself writes is
  translated.

## Not done: the game itself in Spanish

Screen reading was built and tested on an English game client. With the
game set to Spanish (all unverified, no Spanish captures yet):

- Item tooltips: should work, since names match in either language.
- Quests in progress (logbook, trader pages): the quest titles match in
  either language, but the tab detection reads the screen's layout only,
  so it should work.
- Workshop station page: the title parser expects `LEVEL`; a Spanish
  title (`NIVEL`?) isn't parsed.
- Map: the header (`DAM BATTLEGROUNDS - 18:45`) and the place-name labels
  used to locate the map view are matched against English text, so map
  markers would not follow the map in a Spanish client.

Spanish captures of those screens would settle these.
